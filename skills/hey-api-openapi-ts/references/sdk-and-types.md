# SDK, TypeScript, and Schemas (core plugins)

These are the core plugins. Types and SDK are generated by default; the JSON-schema plugin is opt-in.

## TypeScript plugin (`@hey-api/typescript`)

Generates `types.gen.ts`: interfaces/types for every schema, and per-operation `XData`, `XResponses`, `XErrors` types. Zero runtime cost (erased at compile). On by default. You rarely configure it beyond enums/naming; see `https://heyapi.dev/docs/openapi/typescript/plugins/typescript`.

Use these types directly when you need the shape without calling:

```ts
import type { Pet, AddPetData } from './client/types.gen';
```

## SDK plugin (`@hey-api/sdk`)

Generates `sdk.gen.ts`: a typed function (or class method) per operation, on top of the client, with auth/validation/transformation wiring. On by default. Add it explicitly to configure:

```ts
plugins: [
  { name: '@hey-api/sdk', /* options */ },
]
```

### Flat vs instance (`operations.strategy`)

**Flat** (default, `strategy: 'flat'`) — tree-shakeable standalone functions. Best bundle size:

```ts
// generated
export const addPet = (options: Options<AddPetData>) => { /* ... */ };

// usage
import { addPet } from './client/sdk.gen';
await addPet({ body: { name: 'Kitty' } });
```

**Instance** (`strategy: 'single'`) — a class with methods. No tree-shaking (larger bundle) but some prefer the grouping:

```ts
{ name: '@hey-api/sdk', operations: { strategy: 'single' } }
```

```ts
// generated
export class Sdk extends HeyApiClient {
  public addPet(options: Options<AddPetData>) { /* ... */ }
}
```

### Naming the class (`operations.containerName`)

```ts
{ name: '@hey-api/sdk', operations: { containerName: 'PetStore', strategy: 'single' } }
// -> export class PetStore extends HeyApiClient { ... }
```

### Nesting / renaming (`operations.nesting`)

Group and rename methods. Presets exist, but a function gives full control. Example — nest pet endpoints under a `pet` accessor so `addPet()` becomes `petStore.pet.add()`:

```ts
{
  name: '@hey-api/sdk',
  operations: {
    containerName: 'PetStore',
    strategy: 'single',
    nesting(operation) {
      if (operation.path === '/pet' || operation.path === '/pet/{petId}') {
        return [
          'pet',
          operation.operationId?.replace(/Pet/, '') ||
            operation.method.toLowerCase(),
        ];
      }
      return OperationPath.fromOperationId()(operation); // built-in helper for the rest
    },
  },
}
```

### Auth (`auth`)

```ts
{ name: '@hey-api/sdk', auth: true }
```

With `auth: true`, the SDK calls the client's `auth()` callback and serializes the result per the spec's security scheme. Built-in support is `bearer` and `basic`. Return the token from the client config:

```ts
client.setConfig({ auth: () => '<token>' });
```

### Validators (`validator`)

Runtime validation is off by default (it costs CPU). Turn it on:

```ts
// auto-add a validator with defaults
{ name: '@hey-api/sdk', validator: 'zod' }   // or true, valibot, etc.

// validate only one direction
{ name: '@hey-api/sdk', validator: { request: 'zod' } }
{ name: '@hey-api/sdk', validator: { response: 'zod' } }
```

Setting `validator` auto-adds the matching validator plugin with defaults. To customize the schemas, also list the validator plugin explicitly (`{ name: 'zod', ... }`) and set `validator: true` to auto-pick it. See `validators.md`.

### Transformers (`transformer`)

Like validators but **responses only** — used to coerce/shape response data (e.g. parse date strings into `Date`):

```ts
{ name: '@hey-api/sdk', transformer: true } // or 'valibot', etc.
```

### Generated code examples (`examples`)

The SDK can emit ready-to-paste usage examples per operation. Off by default:

```ts
{
  name: '@hey-api/sdk',
  examples: {
    moduleName: '@petstore/client', // what users import from
    setupName: 'client',            // how they instantiate (once per app)
  },
  operations: { containerName: 'PetStore', strategy: 'single' },
}
```

`importSetup` lets you control instantiation that needs an API key, etc.

## JSON Schemas plugin (`@hey-api/schemas`)

Opt-in. Emits the raw JSON schemas from the spec as exported objects — useful for feeding other tooling or runtime introspection. Add `'@hey-api/schemas'` to plugins. See `https://heyapi.dev/docs/openapi/typescript/plugins/schemas`.

## Using the SDK in app code

```ts
import { getPetById, addPet } from './client/sdk.gen';

const { data, error } = await getPetById({ path: { petId: 1 } });
if (error) { /* handle typed error */ }

await addPet({
  body: { name: 'Rex', photoUrls: [] },
  headers: { 'X-Trace': 'abc' },
  query: { dryRun: true },
});
```

Options keys (`path`, `query`, `body`, `headers`) are all typed from the spec. Pass `client` or `baseUrl` to override the instance per call.
